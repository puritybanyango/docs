eLoop uses JWT (JSON Web Token) authentication to secure every API request. When you sign in, eLoop validates your credentials and issues a session token tied to your account and role. You must include this token in the `Authorization` header of every subsequent API call — without it, requests will be rejected.

## Signing In

To authenticate, send your email address and password to the `/auth/login` endpoint. On success, eLoop returns a JWT access token you can use immediately.

```bash
curl -X POST https://api.eloop.io/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email": "you@yourcompany.com", "password": "your-password"}'
```

A successful response looks like this:

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "bearer"
}
```

Copy the value of `access_token` — you will use it in every subsequent request.

<Warning>
  Store your token securely. Never commit it to source control, paste it into a chat tool, or share it with anyone outside your organization. Treat it the same way you would treat a password.
</Warning>

## Two-Factor Authentication

eLoop requires two-factor authentication (2FA) for every user account — it is not optional. When you sign in, you must provide both your password and a time-based one-time passcode (TOTP) generated by an authenticator app.

<Steps>
  <Step title="Set up your authenticator app">
    During account setup, eLoop presents a QR code. Scan it with an authenticator app such as Google Authenticator or Authy. This links the app to your eLoop account and begins generating six-digit TOTP codes that refresh every 30 seconds.
  </Step>
  <Step title="Enter your TOTP code at sign-in">
    After entering your email and password, submit the current six-digit code from your authenticator app. A correct password alone is not enough — both factors are required before a full access token is issued.
  </Step>
</Steps>

<Note>
  Keep your authenticator app installed and accessible. If you lose access to your TOTP device, contact your organization's Admin to recover your account.
</Note>

## Using Your Token

Once you have your access token, attach it to every API request as a `Bearer` token in the `Authorization` header.

```bash
curl https://api.eloop.io/user/me \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"
```

Replace `YOUR_ACCESS_TOKEN` with the value returned at sign-in. If the token is missing, malformed, or expired, the API returns `401 Unauthorized`.

## Password Reset

If you forget your password, you can reset it yourself without contacting support.

<Steps>
  <Step title="Request a reset email">
    Send a POST request to `/auth/forgot-password` with your registered email address:

    ```bash
    curl -X POST https://api.eloop.io/auth/forgot-password \
      -H "Content-Type: application/json" \
      -d '{"email": "you@yourcompany.com"}'
    ```

    You are limited to 5 reset requests per 15 minutes from the same IP address.
  </Step>
  <Step title="Check your inbox">
    Open the password reset email sent to the address you provided. The email contains a time-limited reset link — use it promptly before it expires.
  </Step>
  <Step title="Set your new password">
    Follow the link from the email and POST your new password to `/auth/reset-password`, including the token from the link:

    ```bash
    curl -X POST https://api.eloop.io/auth/reset-password \
      -H "Content-Type: application/json" \
      -d '{
        "token": "reset-token-from-email-link",
        "new_password": "your-new-password",
        "confirm_password": "your-new-password"
      }'
    ```

    Once confirmed, sign in again using your new credentials to obtain a fresh token.
  </Step>
</Steps>

## Session Management

Your JWT token is stored in the browser session while you are logged in to the eLoop web app. You do not need to re-authenticate between page loads as long as your session remains active.

When you log out, eLoop immediately wipes all stored authorization tokens and redirects you to the welcome screen. Any attempt to use a token from a logged-out session returns `401 Unauthorized`.

## Rate Limiting and Account Lockout

To protect your account from automated attacks, eLoop applies the following limits:

| Endpoint | Limit |
|---|---|
| `POST /auth/login` | 5 requests per minute per IP |
| `POST /auth/forgot-password` | 5 requests per 15 minutes per IP |

After **3 consecutive failed sign-in attempts**, your account is temporarily locked for **15 minutes**, independent of the rate limits above. This blocks slow, distributed credential-guessing attacks that stay under the per-minute threshold. Wait 15 minutes and try again, or contact your Admin if you need immediate access.

## Common Authentication Errors

If an API call fails with an authentication-related status code, use this table to diagnose and resolve the issue.

| HTTP Status | Meaning | What To Do |
|---|---|---|
| 401 Unauthorized | Token missing, expired, or account locked | Sign in again to get a new token; if locked, wait 15 minutes |
| 403 Forbidden | Your role does not permit this action | Check your account role with your Admin |
| 422 Unprocessable Entity | Invalid request body | Check that `email` and `password` fields are present and correctly formatted |
