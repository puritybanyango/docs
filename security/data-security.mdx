eLoop is designed with security at every layer — from the edge device on your sorting line to the cloud that stores your batch and procurement data. This page explains the protections in place so you can understand exactly how your organization's information is handled.

## Data in Transit

All communication between your devices, the eLoop web app, and the eLoop cloud is encrypted using HTTPS with TLS 1.3. Plain HTTP requests are blocked entirely and will not be accepted by the platform.

## Edge Privacy

The edge device on your sorting line classifies e-waste components locally, on the device itself. Only the lightweight classification result — a component type label such as "PCB" or "battery" — is sent to the eLoop cloud. Raw video and image data are processed entirely on-site and are never transmitted to or stored in the cloud.

This design means sensitive footage of your facility stays within your facility. You get the AI classification intelligence without exposing your operations to unnecessary data transmission.

## Authentication Security

Every API request to eLoop is authenticated using a JWT (JSON Web Token). Tokens are stateless and scoped to the authenticated user's specific role and company, so a token belonging to one user cannot access another user's data or perform actions outside that user's permitted role.

Two-factor authentication (2FA) using a time-based one-time passcode (TOTP) is **mandatory for all users** — it is not optional and is not limited to Admin accounts. A valid password alone is never sufficient to obtain an access token; both factors must be verified.

Sign-in is also protected by rate limiting and account lockout policies. After three consecutive failed attempts, an account is locked for 15 minutes to guard against automated credential-guessing attacks.

## Multi-Tenant Isolation

eLoop is a multi-tenant platform serving recycling centers and refineries. Each company's data — including batch records, device intakes, bookings, and user accounts — is isolated under that company's account. Users authenticated under your organization can only access data that belongs to your organization.

There is no cross-tenant data visibility. A worker at one recycling center cannot view or interact with the records of another company, even if both are using the eLoop platform simultaneously.

## Role-Based Access Control

Access within your organization is governed by three roles. Admins assign roles when provisioning accounts, and role permissions are enforced on every API request.

  <Card title="Admin" icon="shield-check">

  </Card>
  <Card title="Recycling Center Worker" icon="recycle">

  </Card>
  <Card title="Refinery Operator" icon="industry">

If an employee leaves your organization or changes roles, ask your Admin to deactivate or update their account immediately. Deactivating an account invalidates all active tokens for that user at the next request.

<Tip>
  Register your password recovery email to a company-controlled inbox rather than a personal email address. This ensures that if an employee leaves, your organization retains control of the account recovery process and is not locked out of critical Admin access.
</Tip>

## Password Storage

User passwords are never stored in plaintext. eLoop uses an industry-standard, salted adaptive hashing algorithm, which means that even in the unlikely event of a data breach, stored password records cannot be reversed into the original credentials.
