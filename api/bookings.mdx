---

The `/api/booking` endpoints power the procurement workflow in the Digital Showroom. Refinery buyers use these to submit booking requests on verified batches, and recycling centers use them to confirm or cancel those requests.

When a booking is created, it opens in an `in_progress` state. The recycling center operator then confirms or cancels it, and the linked batch status advances in parallel:

```text
Booking: In Progress → Confirmed | Cancelled
Batch:   Listed      → Booked    → Completed
```

---

## POST /api/booking

Submit a booking request for a listed batch in the Digital Showroom. Call this endpoint when a refinery buyer wants to claim a batch and initiate the procurement process.

**Endpoint**
```
POST https://eloop-api.herokuapp.com/api/booking
```

<Note>
  A batch can only have one active booking at a time. If a batch already has an `in_progress` or `confirmed` booking against it, subsequent POST requests for the same `batch_id` will be rejected. Check the batch status using `GET /api/batches/{batch_id}` before submitting a booking request.
</Note>

### Request headers

| Header | Value |
|--------|-------|
| `Authorization` | `Bearer TOKEN` |
| `Content-Type` | `application/json` |

### Request body

<ParamField body="batch_id" type="string" required>
  The unique identifier of the listed batch the buyer wants to procure.
</ParamField>

<ParamField body="user_id" type="string" required>
  The unique identifier of the refinery buyer submitting this booking request.
</ParamField>

### Example request

```bash
curl -X POST https://eloop-api.herokuapp.com/api/booking \
  -H "Authorization: Bearer TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "batch_id": "bat_01HXYZ654321",
    "user_id": "usr_55REF001"
  }'
```

### Example response

```json
{
  "id": "bkg_01HXYZ111222",
  "batch_id": "bat_01HXYZ654321",
  "user_id": "usr_55REF001",
  "status": "in_progress",
  "created_at": "2024-06-02T08:30:00Z"
}
```

### Response fields

<ResponseField name="id" type="string">
  Unique identifier for the newly created booking record.
</ResponseField>

<ResponseField name="batch_id" type="string">
  The batch this booking is linked to.
</ResponseField>

<ResponseField name="user_id" type="string">
  The refinery buyer who submitted this booking request.
</ResponseField>

<ResponseField name="status" type="string">
  The initial booking status. Always `"in_progress"` on creation.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp recording when the booking was submitted.
</ResponseField>

## GET /api/booking/\{booking_id\}

Retrieve the full details of a specific booking record, including its current status and associated batch and buyer IDs.

**Endpoint**
```
GET https://eloop-api.herokuapp.com/api/booking/{booking_id}
```

### Request headers

| Header | Value |
|--------|-------|
| `Authorization` | `Bearer TOKEN` |

### Path parameters

<ParamField path="booking_id" type="string" required>
  The unique identifier of the booking to retrieve.
</ParamField>

### Example request

```bash
curl -X GET https://eloop-api.herokuapp.com/api/booking/bkg_01HXYZ111222 \
  -H "Authorization: Bearer TOKEN"
```

### Example response

```json
{
  "id": "bkg_01HXYZ111222",
  "batch_id": "bat_01HXYZ654321",
  "user_id": "usr_55REF001",
  "status": "confirmed",
  "created_at": "2024-06-02T08:30:00Z",
  "updated_at": "2024-06-02T09:15:00Z"
}
```

### Response fields

<ResponseField name="id" type="string">
  Unique identifier for the booking.
</ResponseField>

<ResponseField name="batch_id" type="string">
  The batch this booking is linked to.
</ResponseField>

<ResponseField name="user_id" type="string">
  The refinery buyer who submitted this booking.
</ResponseField>

<ResponseField name="status" type="string">
  Current booking status: `"in_progress"`, `"confirmed"`, or `"cancelled"`.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp recording when the booking was created.
</ResponseField>

<ResponseField name="updated_at" type="string">
  ISO 8601 timestamp of the most recent status update.
</ResponseField>

## PATCH /api/booking/\{booking_id\}

Update the status of a booking. Recycling center operators use this endpoint to confirm or cancel a pending booking request from a refinery buyer.

**Endpoint**
```
PATCH https://eloop-api.herokuapp.com/api/booking/{booking_id}
```

<Tip>
  Confirming a booking automatically transitions the linked batch status from `listed` to `booked`. You do not need to call `PUT /api/batches/{batch_id}` separately — the status change cascades through both records in a single operation.
</Tip>

### Request headers

| Header | Value |
|--------|-------|
| `Authorization` | `Bearer TOKEN` |
| `Content-Type` | `application/json` |

### Path parameters

<ParamField path="booking_id" type="string" required>
  The unique identifier of the booking to update.
</ParamField>

### Request body

<ParamField body="status" type="string" required>
  The new booking status. Must be one of:
  - `"confirmed"` — the recycling center accepts the buyer's procurement request
  - `"cancelled"` — the booking request is rejected or withdrawn
</ParamField>

### Example: Confirm a booking

```bash
curl -X PATCH https://eloop-api.herokuapp.com/api/booking/bkg_01HXYZ111222 \
  -H "Authorization: Bearer TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "status": "confirmed"
  }'
```

```json
{
  "id": "bkg_01HXYZ111222",
  "batch_id": "bat_01HXYZ654321",
  "user_id": "usr_55REF001",
  "status": "confirmed",
  "created_at": "2024-06-02T08:30:00Z",
  "updated_at": "2024-06-02T09:15:00Z"
}
```

### Example: Cancel a booking

```bash
curl -X PATCH https://eloop-api.herokuapp.com/api/booking/bkg_01HXYZ111222 \
  -H "Authorization: Bearer TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "status": "cancelled"
  }'
```

```json
{
  "id": "bkg_01HXYZ111222",
  "batch_id": "bat_01HXYZ654321",
  "user_id": "usr_55REF001",
  "status": "cancelled",
  "created_at": "2024-06-02T08:30:00Z",
  "updated_at": "2024-06-02T09:45:00Z"
}
```
